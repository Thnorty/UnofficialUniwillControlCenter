# uucc CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A console command, `uucc`, that reads the laptop's status and changes the app's main settings by talking to
the running app over a named pipe.

**Architecture:** `uucc.exe` (a second binary target) parses arguments into a `Request`, sends it as one JSON line over
`\\.\pipe\UnofficialUniwillControlCenter`, and formats the `Reply`. In the app, a pipe server thread hands each request
to the UI thread, where `App::run_cli` resolves names and calls the same `App` methods the window's callbacks call.
The request/reply types live in one module both binaries compile.

**Tech Stack:** Rust 2024, `windows` 0.62 (named pipes, security descriptors), serde/serde_json, Inno Setup 6.7.

**Spec:** `docs/superpowers/specs/2026-10-14-uucc-cli-design.md`

## Global Constraints

- Pipe names: `\\.\pipe\UnofficialUniwillControlCenter`; demo `\\.\pipe\UnofficialUniwillControlCenter.Demo`, used by
  `uucc` when the environment variable `UUCC_DEMO=1`.
- Protocol version 1. One JSON line each way per connection; requests at most 64 KB; a client silent for 5 s is
  dropped.
- Pipe security descriptor SDDL: `D:P(A;;GA;;;<user SID>)S:(ML;;NW;;;ME)`; created with
  `FILE_FLAG_FIRST_PIPE_INSTANCE` and `PIPE_REJECT_REMOTE_CLIENTS`.
- Exit codes: 0 done; 1 bad command or value (message says what's valid); 2 app not running (no `--start`) or not
  started within 15 s; 3 the app couldn't do it (prints the app's message).
- The app waits at most 15 s for the UI thread to answer ("The app didn't answer.", code 3).
- Value words: modes `office|gaming|turbo`; charge `full|balanced|long-life` (app: High capacity, Balanced,
  Stationary); GPU mode `hybrid|intel|nvidia` (`GpuMode::Hybrid/Integrated/Discrete`); display modes `Vibrant`,
  `Cinema`, `Low blue light`, `Custom`; speed `slowest|slow|medium|fast|fastest` or `1`-`5` (app speed 0-4).
- Names match case-insensitively; a unique prefix is enough; exact match wins over prefix.
- Lighting options apply in the order effect, colors, brightness, speed, on/off, linked; the first failure stops the
  rest.
- `uucc` must not link Slint or hardware code; it may use `windows` for `ShellExecuteExW`.
- Version 3.4.0. No attribution lines in commits. Commit per task.

## Review Focus

1. **A normal (non-admin) terminal talking to the elevated app.** Expect it to just work; the Medium integrity label
   is what allows it. Task 2 tests the descriptor's SDDL; Task 7 has the owner run `uucc status` against the real app.
2. **Two `uucc` calls at once** (a Stream Deck double press, a script loop). Expect the second to wait its turn, not
   fail. Task 2 tests two concurrent clients; Task 3's client retries `ERROR_PIPE_BUSY` with `WaitNamedPipeW` for 5 s.
3. **Names with spaces, punctuation or non-ASCII letters** (a setup called "Gece Modu – Sessiz", `"Low blue light"`).
   Expect case-insensitive matching to work on them and the text output to show them intact. Task 1 tests `resolve`
   with these; Task 3 tests that text output keeps them.
4. **The app closing or hung while a command runs.** Expect code 2 if the pipe is gone and code 3 "The app didn't
   answer." if it hangs, never a hang in `uucc`. Task 3 tests a client against a server that never replies (read
   timeout 20 s, code 3).
5. **`uucc --start` when the app stops at its first-start question** (a new install that hasn't accepted the risk
   notice). Expect `uucc` to give up after 15 s with a message saying the app may be waiting for that question, not
   a bare "didn't start". Task 3 tests the `DidntStart` message.

A hardware refusal that arrives after a command returns (EC writes run on the EC thread) is handled by Task 4's
settle step; the demo has no EC, so it's checked in review and on the real laptop in Task 7.

  - `pub struct Envelope { pub version: u32, pub request: Request }`
  - `pub enum Request { Status, Mode(Option<String>), FanBoost(Option<bool>), Profile(Option<String>), Lighting { device: Device, changes: LightingChanges }, Effects, Charge(Option<String>), Setup(Option<String>), Display { on: Option<bool>, mode: Option<String> }, GpuMode(Option<String>) }`
  - `pub enum Device { Keyboard, LightBar }`
  - `pub struct LightingChanges { pub effect: Option<String>, pub colors: Option<Vec<String>>, pub brightness: Option<u8>, pub speed: Option<u8>, pub on: Option<bool>, pub linked: Option<bool> }` (`speed` 0-4, `colors` as `#rrggbb`; `Default`)
  - `pub enum Reply { Ok(serde_json::Value), Error { code: u8, message: String } }`
  - Results: `ModeResult { mode: String, available: Vec<String> }`, `FanBoostResult { on: bool }`,
    `ProfileResult { mode: String, profiles: Vec<String>, active: String }`,
    `LightingResult { device: Device, on: bool, effect: String, effect_name: String, brightness: u8, speed: Option<u8>, colors: Vec<String>, linked: Option<bool> }`,
    `EffectInfo { id: String, name: String, min_colors: usize, max_colors: usize, has_speed: bool }`,
    `EffectsResult { keyboard: Vec<EffectInfo>, light_bar: Option<Vec<EffectInfo>> }`,
    `ChargeResult { charge: String }`, `SetupResult { setups: Vec<String>, applied: Option<String> }`,
    `DisplayResult { on: bool, mode: String, modes: Vec<String> }`,
    `GpuModeResult { mode: String, restart_needed: bool }`,
    `FanResult { rpm: u16, duty: u8 }`,
    `StatusResult { mode: String, fan_boost: bool, profile: String, cpu_temperature: Option<f32>, cpu_load: Option<f32>, gpu_temperature: Option<f32>, gpu_off: bool, cpu_fan: Option<FanResult>, gpu_fan: Option<FanResult>, battery_percent: Option<u8>, charging: bool, on_ac: bool, charge: String, keyboard: LightingResult, light_bar: Option<LightingResult>, display: DisplayResult, gpu_mode: Option<String> }`

    NAME is via `resolve_kind(kind: &str, input, names)` (the plain `resolve` uses "value").

  - `pub fn read_message<T: DeserializeOwned>(r: &mut impl Read) -> io::Result<T>` (reads to `\n` or EOF, errors past
    `MAX_MESSAGE` with `InvalidData`)

  - `pub fn start(name: &str, handle: impl Fn(Envelope) -> Reply + Send + 'static) -> anyhow::Result<()>`: creates

    "CLI server", one connection at a time: read with a 5 s timeout (overlapped read or a watchdog that calls

    loop.
  - `fn security_descriptor() -> anyhow::Result<...>`: token user SID → `ConvertSidToStringSidW` → SDDL from Global
    Constraints → `ConvertStringSecurityDescriptorToSecurityDescriptorW`.
  - `pub(crate) fn sddl_for(sid: &str) -> String` (pure, for the test).

### Task 3: The `uucc` program

**Files:**
- Create: `src/bin/uucc/main.rs`, `src/bin/uucc/args.rs`, `src/bin/uucc/output.rs`, `src/bin/uucc/connect.rs`
- Modify: `Cargo.toml` (`[[bin]] name = "uucc" path = "src/bin/uucc/main.rs"`)

**Interfaces:**
- Consumes: `protocol.rs` via `#[path = "../../cli/protocol.rs"] mod protocol;` in `main.rs`.
- Produces:
  - `args::parse(args: &[String]) -> Result<Command, Usage>` where
    `pub struct Command { pub request: Option<Request>, pub json: bool, pub start: bool }` (`request` is `None` for
    `--help`/`--version`/`help`, which set `pub help: Option<String>` (the topic) / `pub version: bool`), and
    `pub struct Usage(pub String)` (the message, exit code 1).
  - `output::text(request: &Request, result: &serde_json::Value) -> String`; `--json` prints the `Reply::Ok` value
    with `serde_json::to_string_pretty`; errors print `uucc: <message>` to stderr (in JSON mode, the
    `{"error":{...}}` object to stdout).
  - `connect::send(envelope: &Envelope, demo: bool, start: bool) -> Result<Reply, Failure>`, which calls
    `send_with_timeout(name: &str, envelope, start, read_timeout: Duration)` with 20 s;
    `pub enum Failure { NotRunning, DidntStart, NoAnswer, Io(String) }` mapping to codes 2, 2, 3, 3, with
    `fn message(&self) -> String`. `DidntStart`'s message: "Unofficial Uniwill Control Center didn't start within
    15 s. If it's new on this PC, it may be waiting for its first-start question: open it once from Start."
  - `const USAGE: &str` (the commands table from the spec), and one help text per command.
- Parsing rules: words per the spec's table; positional `on|off` for `fan-boost`, `keyboard`, `lightbar`,
  `display`; `--effect`, `--brightness` (0-100), `--speed` (Global Constraints words or 1-5 → 0-4), `--colors`
  (`#rrggbb`/`rrggbb`, comma-separated, stored as `#rrggbb` lowercase), `--linked on|off` (lightbar only),
  `--mode` (display only); `--json`, `--start` anywhere; `--opt=value` and `--opt value` both accepted.
  Mode/charge/gpu-mode words resolve client-side with `resolve` to the canonical word (so `uucc mode t` sends
  `"turbo"`); profiles, setups, effects and display modes travel as typed.
- `--start`: pipe missing → if `schtasks /Query /TN UnofficialUniwillControlCenter` succeeds, `schtasks /Run`; else
  `ShellExecuteExW` verb `runas` on `<uucc's folder>\UnofficialUniwillControlCenter.exe` with `--tray` (missing exe
  → `Failure::DidntStart` with "can't find UnofficialUniwillControlCenter.exe next to uucc"); then poll the pipe
  every 250 ms for 15 s.
- Read timeout on the reply: 20 s (more than the app's own 15 s), then `Failure::NoAnswer`.

  - `GpuMode(Some(..))`: `gpu_mode()` is `None` → code 3 "This laptop has no GPU mode switch."; `bios_writable()`
